Project · November 2026Executive Design Engineering CAD AI

Author: Jonas Bonnett
What it is: A private engineering portfolio prototype — an AI-assisted engineering design and manufacturing documentation platform. An initial mobile-friendly prototype (HTML/CSS/JS) that records project requirements and generates preliminary manufacturing documentation templates without requiring any paid API
Built with: HTML, CSS, JavaScript — Python 3.10+ optional for tests and backend components
Status: Code prototype — not a live app and not in production use; all example data fictional, labeled PRELIMINARY — NOT RELEASED FOR PRODUCTION

What it does

Manufacturing documentation starts with requirements: what the project must do, written down before anything is designed or built. This prototype records those requirements and turns them into preliminary manufacturing documentation templates — the paperwork a design needs before it can be made, checked, and released. It is the engineering depth behind the no-code builds elsewhere on this site: the same instinct as the Manufacturing Documentation Studio, but built as code, with a real repository structure instead of a generated app. One prototype holds:

  • Requirements capture — create a project, add its requirements, and hold them as the record the design is measured against.
  • Preliminary documentation templates — generate manufacturing documentation templates from the requirements, editable and exportable.
  • Mobile-friendly by design — the frontend runs in a mobile browser or on desktop, so requirements can be recorded where the work happens.
  • No paid services — the prototype runs without any paid API or paid service, and no API keys are used.

The structure

The prototype is a real repository, not a sketch — with the structure a documentation platform actually needs:

  • app/ — backend and frontend, the working prototype itself.
  • cad/ — the CAD side of the platform.
  • docs/ — a project charter, system architecture, engineering-safety rules, and a setup guide — the platform documented the way an engineering deliverable should be.
  • examples/ — worked examples of the prototype in use.
  • templates/ — the editable documentation templates the prototype generates.
  • tests/ — tests for the backend components.
  • README and LICENSE-DECISION.md — how to run it, and the licensing decision recorded alongside the code.

How it runs

Open app/frontend/index.html in a mobile browser or on desktop to use the prototype — no backend is required for the first milestone. Use the “New Project” button to create a project and add requirements, then export requirements or templates from the UI, or find the editable templates in the templates/ folder. Dependencies: none required to run the frontend; Python 3.10+ is optional for running tests or backend components.

Honest framing

This is a code prototype, not a live app and not in production use, and this page does not claim otherwise. All example data is fictional and labeled PRELIMINARY — NOT RELEASED FOR PRODUCTION — and no paid services or API keys are used. What exists is real: the frontend and backend, the docs, the templates, and the tests, and the prototype runs. But it is a beginning — the engineering depth behind the no-code builds, showing how he thinks about a documentation platform in code, not a finished product.

Why it’s here

The through-line of his work is the same everywhere on this site: document the thing, then improve the process that builds the thing. He has written SOPs, managed blueprint lifecycles and engineering revisions in Windchill, built a Word/Excel tracker for pouch cell holders with pass/fail test results, and trained technicians on repeatable procedures. The Manufacturing Documentation Studio is that discipline turned into a documentation tool; GRANDMASTER AI is the same instinct at the orchestration level, EngiFlow AI at the project level, and EngiMatrix Executive at the executive level. This prototype is that instinct in code: requirements in, documentation templates out, with the structure — docs, tests, templates — that a real platform needs underneath.

Skills this demonstrates

Requirements capture and documentation-template design; repository structure for an engineering platform — app, CAD, docs, examples, templates, tests; writing a project charter, system architecture, and safety rules alongside the code; and building a working prototype with plain HTML, CSS, and JavaScript — the same instinct as the Documentation Studio, GRANDMASTER AI, EngiFlow AI, EngiMatrix Executive, JDOGG ROCKSTAR, and Scripted CAD: he builds the systems that run the work.
